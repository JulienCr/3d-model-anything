# Private rooms on several computers

The rooms `atrium`, `trone` and `couloir` are rebuilt from private iPhone scans. Their code is in git, their data is not.

## What is where

| What | Where |
|---|---|
| Code: `demos/<room>/`, `packages/room-runtime/`, `tools/`, `docs/` | Branch `environments` of the fork `github.com/JulienCr/3d-model-anything` |
| Data: room plan, prepared photos and textures, scans, raw capture, exports | The shared drive folder `.../Salle/3D/3d-model-anything/<Room>/` (Google Drive) |
| Local copy of the data | `data/demos/<room>/room.json`, `data/web-assets/<room>/`, `data/scans/<room>/`, `data/captures-in/<room>/`, `data/exports/<room>/` (all git-ignored) |

Per room, the drive folder holds `room.json`, `web-assets/`, `scans/`, `capture/<Room>-iphone-export.zip` and `exports/`. The raw capture is the source of truth; the rest can be regenerated from it (`node tools/rooms.mjs pipeline <room>`), the drive copy only saves the time.

## New computer

```bash
git clone --branch environments https://github.com/JulienCr/3d-model-anything.git
cd 3d-model-anything
npm ci            # if ~/.npmrc points at an unreachable private registry: npm ci --registry=https://registry.npmjs.org/
```

1. Install Drive for desktop, sign in, then right-click the shared folder `3d-model-anything` > Offline access > Available offline and wait for the sync to finish. In streaming mode every file is downloaded on first read, which is slow and can stall.
2. Restore the data: `node tools/drive-sync.mjs pull` (about 1.7 GB, needs `unzip`). The drive is auto-detected under `~/Library/CloudStorage/GoogleDrive-*/`. If several folders match (the same shared drive mounted by two Google accounts, each with its own cache), the script stops and lists them: set `DRIVE_DIR` to the `3d-model-anything` folder of the account that is synced.
3. `npm run dev`, then open `/?room=trone`, `/?room=atrium`, `/?room=couloir`.

To rebuild the Blender exports: `npm run export:all`, then `npm run export:check` (see [export.md](export.md)).

## drive-sync

```bash
node tools/drive-sync.mjs status [room ...]               # what is present on each side, sizes compared
node tools/drive-sync.mjs pull   [room ...] [--dry-run] [--force] [--with-exports]
node tools/drive-sync.mjs push   [room ...] [--dry-run] [--force] [--with-exports]
```

- Nothing is ever deleted, on either side. A file already present on the destination with a different size is left alone and reported unless `--force`.
- Re-running is cheap: what already matches (same file list and sizes) is skipped.
- The capture zip is extracted without its top folder, into a temporary directory first, then moved into `data/captures-in/<room>`.
- `exports/` is only synced with `--with-exports` (they are regenerated by `npm run export:all`).
- Copies go through a `.drive-sync-stage` folder next to the destination and are moved into place after a size check: an interrupted run never leaves a half-written file, and rerunning resumes.
- A copy with no byte progress for 90 s (`DRIVE_SYNC_STALL_SECONDS`) is killed, retried once, then fails naming the file; set the folder to Available offline and rerun. Progress (files, bytes) is printed every few seconds.
- `push` zips `data/captures-in/<room>` only when the drive has no capture archive yet.

`node --test tools/drive-sync.test.mjs` checks the tool against a fake drive in a temp directory (pull, push, idempotence, stall handling, auto-detection).

## Adding a room

1. Add the code and register it in `demos/index.ts` and `tools/rooms.json` (see "Adding a room" in [export.md](export.md)).
2. Add `"drive": "<Folder>"` to its entry in `tools/rooms.json`; the folder is created on the drive by `push`.
3. Git-ignore its data in `.gitignore` (`data/demos/<room>/`, `data/web-assets/<room>/`).
4. `node tools/drive-sync.mjs push <room> --with-exports`.

## Not in git, on purpose

Scans, photos, room plans (`room.json`) and the raw captures show the inside of a private place and the people who live there. They are never committed: the paths are git-ignored and `drive-sync` only moves them between this checkout and the private drive. The branch `environments` is deliberately not meant for upstream; the generic tooling lives in the upstream PR branch it is built on.
